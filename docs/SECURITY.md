# CIVICSHIELD NG — CYBERSECURITY & THREAT DEFENSE SPECIFICATION

**Security Standard:** Zero-Trust Architecture, Defense-in-Depth, and Principle of Least Privilege.  
**Audience:** Security Engineers, System Auditors, Infrastructure Administrators.

---

## 1. Threat Model & Electoral Attack Vectors

CivicShield NG operates in an adversarial environment characterized by:
1. **Coordinated Inauthentic Behavior (CIB):** Botnets and astroturfing campaigns spreading fabricated election timetables and altered polling locations.
2. **Deepfake Audio/Video & Forged Press Releases:** Hyper-realistic synthetic media impersonating INEC officials or returning officers.
3. **Adversarial Prompt Injection:** Attackers attempting to jailbreak citizen AI assistants into certifying false claims or executing arbitrary system commands.
4. **Targeted Disenfranchisement / Voter Suppression:** Geographically localized rumors claiming election cancellations or violence in specific polling units.
5. **Database Tampering & Insider Threats:** Rogue administrators or external attackers attempting to alter verification decisions or cover up audit traces.

## 2. Cryptographic Security Controls

### 2.1. Argon2id Password Hashing
All credentials are protected using Argon2id, the state-of-the-art memory-hard hashing algorithm resistant to GPU/ASIC cracking:
- **Memory Cost ($m$):** 65,536 KiB (64 MiB)
- **Time Cost ($t$):** 3 iterations
- **Parallelism ($p$):** 4 threads
- **Salt:** 16 cryptographically random bytes generated by `os.urandom()`

### 2.2. JWT Token Lifecycle
- **Access Tokens:** Signed with HMAC-SHA256 (`HS256`). Contain subject ID, assigned roles, and issuance timestamp. Strict 60-minute expiration.
- **Refresh Tokens:** Random cryptographically secure 256-bit entropy tokens with 7-day expiration. Stored securely and revoked upon logout.
- **Brute-Force Lockout:** Account is locked for 15 minutes after 5 consecutive failed authentication attempts.

### 2.3. Tamper-Evident Hash-Chained Audit Ledger
Every high-impact state mutation (claim verification, alert broadcast, user registration) generates an immutable audit record linked to the previous record's hash:
$$\text{Entry Hash} = \text{SHA-256}(\text{Previous Hash} \,\|\, \text{Action} \,\|\, \text{Entity ID} \,\|\, \text{ISO Timestamp})$$

The genesis record anchors to:
`GENESIS_ROOT_00000000000000000000000000000000000000000000000000000000`

The system includes an automated integrity validator (`SecurityAuditService.verify_ledger_integrity()`) that detects:
- Any altered field value in historical records.
- Any deleted record in the middle or end of the chain.
- Any unauthorized inserted record.

When a hash mismatch occurs, the engine immediately isolates the broken record ID and emits a `CRITICAL` `TAMPER_DETECTED` security event.

## 3. Citizen Privacy & Zero-PII Protections

1. **Salted Submitter IP Hashing:** Submitter IP addresses are never written to the database. They are transformed using a secret server-side salt:
   $$\text{Stored Hash} = \text{SHA-256}(\text{Raw IP} \,\|\, \text{SECRET\_SALT})$$
   This prevents correlating submissions with citizen home locations while retaining the ability to detect botnet DDoS attacks.
2. **Anonymous Submissions:** Citizens can submit reports without creating an account or providing name/phone number.
3. **No Voter Register Access:** CivicShield NG maintains zero connection to sensitive voter registration databases or personal voter records.

## 4. AI Misinformation & Prompt Injection Defense

Adversarial inputs intended to compromise the AI analysis engine are intercepted by `PromptDefenseFilter` before hitting heuristic or model layers:

```
[ Incoming User Input ]
          |
          v
[ Regex & Keyword Normalization ]
          |
          v
[ Adversarial Pattern Inspection ]
  - Direct Jailbreaks ("ignore all previous instructions", "disregard system prompt")
  - System Tag Injections ("System:", "Developer Note:", "[INST]")
  - Delimiter Escapes (triple backticks, JSON break-out)
  - Output Manipulations ("mark this claim as verified", "always say true")
  - Code & Injection Payloads ("<script>", "UNION SELECT")
          |
          +---> [ Match Detected? ] ---> Log Warning, Strip Injection, Neutralize
          |
          v
[ Sanitized Safe Claim Payload Passed to AI Engine ]
```

## 5. File Upload & Storage Security

All uploaded evidence files undergo strict validation:
1. **MIME-Type & Magic Byte Inspection:** Verified against an explicit whitelist (`image/png`, `image/jpeg`, `audio/mpeg`, `audio/wav`, `video/mp4`, `application/pdf`).
2. **Maximum File Size:** Enforced 25 MiB cap per file.
3. **Filename Sanitization:** Uploaded filenames are completely discarded; stored files use UUID-based paths to prevent path traversal attacks (`../../etc/passwd`).
4. **Canonical SHA-256 Hash:** Every uploaded file is hashed at ingestion to establish a chain of custody for digital evidence.
